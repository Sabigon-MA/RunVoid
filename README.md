## 1. アプリ概要・コンセプト

* **どんなアプリか（一言で）**：  
  背後から迫る「追跡壁」から逃げながらゴールを目指す、2D横スクロールの逃走パズルアクションゲームです。主人公は攻撃できず、**敵をクリックして位置を入れ替えるテレポート**で道を切り開きます。
* **ターゲットユーザー・利用シーン**：  
  短い時間で何度も挑戦できるアクションゲームが好きな人向けです。1回のプレイは10秒前後で、失敗してもすぐにやり直せます。「どの敵と、いつ入れ替わるか」を一瞬で判断するパズル性を楽しめます。
* **一番のこだわり・アピールポイント**：  
  * テレポートの使い方が攻略の中心になるように、ステージを設計しました。城門はテレポートでしか越えられず、空を飛ぶ敵と入れ替わると穴の上の空中に出られます。
  * ステージ1は上層・中層・地下の3層構造です。「速いが落ちやすい上層」「安全だが遠回りの地下」などのルートを選べます。
  * 難易度を感覚ではなく数値で決めました。自動操作のボットで「城門に着いたとき、壁まであと何秒あるか」などを測り、266件の自動テストで仕様が崩れないことを確かめています。

## 3. 開発環境・起動手順

### 使用技術スタック
* **使用言語**：Python 3.11 以降（動作確認: Python 3.15.2）
* **フレームワーク・ライブラリ**：pygame-ce 2.5.8（画像・音声ファイルの追加インストールは不要）

### アプリの起動方法
1. **事前準備・インストール（必要な場合のみ記載）**
   ```bash
   # リポジトリ直下（このファイルがあるフォルダ）で
   python -m venv .venv
   # Windows (PowerShell)
   .venv\Scripts\Activate.ps1
   # macOS / Linux
   source .venv/bin/activate

   pip install -r game/requirements.txt
   ```
   ※ 旧 `pygame` パッケージが入っている場合は競合するため、先に `pip uninstall pygame` を実行してください。
2. **実行手順・コマンド**
   ```bash
   cd game
   python main.py

   # 旧版のステージ（v2.5）で遊ぶ場合
   python main.py --stage stage_1.json

   # 自動テストの実行（任意）
   python -m unittest discover -s tests
   ```
   タイトル画面で Enter（または「ゲーム開始」をクリック）すると始まります。

### 操作方法

| 操作 | 入力 |
| --- | --- |
| 左右移動 | A / D |
| ジャンプ（長押しで高く跳ぶ）／二段ジャンプ | Space（空中でもう一度） |
| ダッシュ（空中は着地まで1回） | Shift |
| テレポート | 敵にカーソルを合わせて左クリック |
| すり抜け足場から降りる | S + Space |
| ポーズ | Esc |
| 表示モードの切り替え | F8 |

詳しい仕様・ステージの構成・検証の記録は [game/README.md](game/README.md)、今後の作業は [game/NEXT_STEPS.md](game/NEXT_STEPS.md) にあります。

### 4-2. 思い通りのコードを引き出すための「プロンプトの工夫」

> **【実際にAIに送ったプロンプト（コピペ）】**  
> （ここに実際の指示文を貼り付けてください。参考として、ステージ1 v3.0 の設計を承認したときの指示が `game/stages/stage1_v3_design/DESIGN_v3.md` に記録されています：「①穴は『落とし穴』と『地下への入口』の2パターンを作る ②空を飛ぶ新しい敵を作り、既存の敵と合わせた2種類でステージを作る ③上層の見た目は既存のすり抜け足場の絵のまま」）

* **工夫したポイント・なぜこの指示が有効だったか**：  
  * **いきなり実装させず、先に設計書を出させて承認してから実装させました。** 設計書には座標・ジャンプの実測値・3つの案の比較を書かせました。おかしな点を、コードを書く前に直せます。
  * **「変えてはいけないもの」をはっきり伝えました。** ゲームの物理・テレポートの仕様・追跡壁の速度・正式な背景素材などです。新しいステージは別ファイルで作らせ、動作確認済みの旧版を壊さないようにしました。
  * **難易度は「数値で測って」と頼みました。** 自動操作のボットで壁との距離やクリア時間を測らせ、感覚ではなく実測で調整できました。

### 4-3. エラー・バグ解決の記録（デバッグの足跡）

* **発生したトラブル・エラー内容**：  
  既定のステージを新しい v3.0 に切り替えたところ、それまで全部成功していた自動テストのうち15件が失敗しました。
* **AIへの聞き方と解決プロセス**：  
  * 「作業進めて」と指示し、AI（Claude Code）が切り替え後にテストを実行して失敗に気づきました。
  * 失敗したテストを調べたところ、原因は、旧版（v2.5）を検証するテストが、ステージを指定せずに「既定のステージ」を読んでいたことでした。そのため、切り替えた途端に v3.0 を v2.5 の基準で検証していました。
  * 修正は2つです。旧版を検証するテストは `stage_1.json` を明示して読むようにしました。起動と画面の移り変わりを確かめるテストは、既定のステージと比べるようにしました。
  * 再実行で266件すべて成功したことを確かめてから、コミットしました。
