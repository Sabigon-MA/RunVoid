# candidates_v4：ステージ1背景の局所補修候補（採用なし）

**結論：不採用。** 原画1672×941のRGBA（alpha含む）は全レイヤーで完全一致した（変化0画素、PNG保存後に再読込して確認）。
ただし、新たに生成した境界は、事前に宣言した基準と目視の両方で、すべて不合格。
L3右はv3の画素をそのまま使う保留候補で、再生成も採用もしていない。
ゲームの設定・コード・テスト、draft_v1、finish_v2、v3、Codexの各フォルダは変更していない（`candidates_v4/` 以下にファイルを追加しただけ）。
生成前の方針と実現可能性の分析は `README_prep_v4.md`、機械可読の一覧は `final_candidate_manifest.json`。

## v3から変えた点
- 文脈を各側546px・全高から128px・必要な行だけに絞った。生成ツールには境界の画素が2.7〜4.3倍の大きさで見える。
- 新しく描く部分だけに、輪郭・描画禁止範囲・肋骨の先端を描いてよい範囲のガイドを付けた（参照専用で、候補には合成しない）。
- L1は霧と丘だけを描く別ジョブにした。v3のプロンプトは、境界で窓が切れていると誤って記述していた。
- 位置合わせのずれは±3px、両側の最適値が一致する場合だけ適用。合格条件は生成前に数値で宣言した。ぼかし・混合はしていない。
- 最終的なキャンバス寸法と原画の位置はv3と同じ。保護マスクはv3と画素単位で一致する。

## 技術上の限界
- 内蔵image_genにはマスクを強制する仕組みも出力寸法の指定もない（L2は1254×1254で返された）。どのジョブも文脈を描き直す。
  L1では左側の文脈から大聖堂が消え、位置合わせ誤差は99だった。文脈を小さくしても、境界の画素を一致させる効果はなかった。
- **L2外周では今回の補完案が成立しなかった**。原画x=0では、肋骨と壁が高さ約480pxにわたって切れている。
  今回の低い瓦礫と接続端付近の短い肋骨に限定したガイドでは、この断面を自然につなげられなかった。
  ただし、元の輪郭・太さ・方向を維持した既存の肋骨の延長は仕様上許容されており、新しい建築物の追加とは区別する。
  今回の試行は、そのような延長を含むすべての局所補完が不可能であることを示すものではない。実現可能性は未検証。
- G3の輪郭判定（alpha≥8）は、まばらな草の先端にも厳しく反応する。目視で自然なL3右（v3）も、このゲートでは不合格になる。
  事前に宣言した基準なので、後から変更はしていない。
