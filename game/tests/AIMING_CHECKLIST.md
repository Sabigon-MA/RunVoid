# v2.2 テレポート照準検証

## 実施結果

**実画面での照準一致は未検証です。DPI・サイズ別の成功を確認した結果ではありません。**

- Windows / Python 3.13.4 / pygame-ce 2.5.8 / SDL 2.32.10。
- SDL dummyによる116件成功（既存110件＋`test_aiming.py`の6件）。
- ネイティブSDLウィンドウは起動し、状態出力でクライアントと内部Surfaceが960×540であることを確認。
- `GetDpiForWindow`は96。ただしWindows設定の100%を目視確認した結果ではなく、倍率の合格根拠にしない。
- Orcaの前面化付き画面取得を試みたが、別ウィンドウで遮られ、ゲーム画面を観察できなかった。OSクリックは実行していない。
- Windowsの表示倍率は変更していない。125%・150%は実施していない。検証プロセスは終了済み。

物理座標をテスト側で割り算するだけの検査も、SDLの実変換の証明にはならない。

## 起動手順

READMEの手順でpygame-ceを導入した環境から実行する。

```powershell
# リポジトリ直下：自動回帰テスト
python -B -m unittest discover -s game/tests -v

# 新しい出力先を毎回使用する
Remove-Item Env:SDL_VIDEODRIVER -ErrorAction SilentlyContinue
$aimOutput = Join-Path $env:TEMP ('runvoid-aim-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
python -B game/tests/manual_aim_probe.py --output $aimOutput
```

診断スクリプトは製品のGame・描画・入力・対象選択・交換処理を使用する。
診断用に敵の移動・飛びかかりと壁を停止し、物理時間も最初は停止する。
通常プレイ全体の合格を保証するものではない。dummyドライバーでは起動を拒否する。
覆われている場合は、手動で検証ウィンドウを前面に出す。

| キー | 診断用動作 |
| --- | --- |
| R | 初期化（位置・CD・交換回数も戻す） |
| C | カメラを右へ80pxずらす |
| Space | 通常の固定物理更新を開始／停止 |
| A / D / Shift | 物理更新中の通常移動・ダッシュ |
| Esc | 終了 |

Spaceは診断操作に使うためジャンプ入力にならない。
ジャンプを含む確認は最後に `python -B game/main.py` でも実施する。
OSカーソルを表示してゲーム内照準と比較できる。

- `state.json`：サイズ、ウィンドウDPI、内部マウス座標、カメラ、対象、CD、回数。
- `clicks.jsonl`：届いたボタンイベントの内部座標、選択対象、更新前後の状態。
- 静止中はCDも停止する。成功後はRで戻すかSpaceでCDを進める。
- スクリプトは任意の`command.json`も受け付ける。前回の終了コマンドと混ざらないよう出力先を分ける。

## サイズ・倍率別の結果表

各セルで以下A〜Eを実施し、合格／不合格と証跡名を記入する。
サイズは外枠ではなくクライアント領域の目標値。実寸は`state.json`で記録する。
モニターに収まらない条件はその旨を記録し、無理に合格としない。

Windows「設定 → システム → ディスプレイ → 拡大縮小」で倍率を確認・変更する。
毎回スクリプトを終了・再起動し、同じモニターで実施する。サインアウトを要求された場合は作業を保存して従う。
未実施の条件は未検証にし、最後に元の倍率へ戻す。モニター間移動は別条件として記録する。

ウィンドウ端のドラッグでサイズを変える。正確なサイズを要求する場合は、別のPowerShellから診断コマンドを使える。
`$aimOutput`には起動時と同じ出力先を指定する。

```powershell
@{ id = [guid]::NewGuid().ToString(); size = @(1200,600); reset = $true; live = $false } |
    ConvertTo-Json | Set-Content -Encoding utf8 (Join-Path $aimOutput 'command.json')
Get-Content (Join-Path $aimOutput 'state.json')
```

### A. 静止した敵

- [ ] Rで戻し、E01の中央にOSカーソル先端を合わせる。ゲーム内照準も同じ位置にある。
- [ ] 輪郭表示が対象に重なり、`hover`がE01となる。
- [ ] クリック後の`selected`がE01、回数が0→1、CDが2.0となる。
- [ ] Rを挟んで敵の左右・上端でも確認。選択余白は内部6pxなので、描画シルエットの輪郭そのものとは異なる。
- [ ] 選択矩形から十分離れた空白では失敗する。一方向への数pxのずれも記録する。

### B. サイズ・縦横比

- [ ] リサイズ後も内部Surfaceが960×540。
- [ ] 拡大・縮小それぞれでAを確認。
- [ ] 横長・縦長で実際の表示領域と上下／左右の余白を記録する。
- [ ] 敵中央、ゲーム表示領域の四辺付近で照準がずれない。
- [ ] 余白をクリックしても敵を誤選択せず、CDを消費しない。
- [ ] リサイズ直後の最初のクリック、カーソルがウィンドウ外から戻った直後も一致する。

### C. Windows倍率

- [ ] Windows設定画面で100%／125%／150%をそれぞれ確認する。
- [ ] 各倍率で再起動し、A・Bを実施する。
- [ ] ウィンドウDPIも併記するが、その値だけで設定倍率の確認を代替しない。
- [ ] 不一致があれば倍率・モニター・実寸・対象・イベント座標・画像を保存する。

### D. カメラ移動・交換直後

- [ ] Rの後にCを押し、移動後に表示されるE01を選択・交換できる。
- [ ] 交換直後、別の敵へ照準を動かすと正しい対象へ切り替わる。
- [ ] CD中は対象が正しくても交換できず、CDが2秒へ再設定されない。
- [ ] Spaceで物理更新を開始し、Dでカメラを動かしながら敵／空白への選択切替を確認する。
- [ ] 通常ゲームでも移動・ジャンプ・ダッシュ中と交換後の再照準を確認する。

### E. 選択失敗とCD

- [ ] READYで空白・画面端・余白をクリックしてもCD=0、回数と位置が不変。
- [ ] CD中の空白／敵へのクリックでは回数が増えず、CDが増加・再設定されない。
- [ ] 物理更新中は時間経過分だけCDが減る。
- [ ] 画面外の敵、カメラ移動前の古い表示位置では誤交換しない。
